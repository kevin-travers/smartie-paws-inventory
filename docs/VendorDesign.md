# Inventory Service – VENDOR REST API Design

### Headers
| Header | Direction | Purpose |
| ----- | ----- | ----- |
| `Authorization: Bearer <token>`  | Request | Authentication (OAuth2 / JWT) |
| `Content-Type: application/json`  | Request | Payload format |
| `Idempotency-Key`  | Request | Safe retries for `POST` operations |
| `If-Match`  | Request | Optimistic locking on updates |
| `X-Trace-Id`  | Both | Distributed tracing |
| `Etag`  | Response | Resource version |

### Vendor

Represents a supplier you buy inventory from. Every `PurchaseOrder` records which Vendor it came from, so purchase history and (eventually) vendor spend can be tracked. Vendors are global in this MVP -- there's no organization/space scoping anymore, since the system now has a single shared inventory with no multi-tenancy.

| Column | Type | Nullable | Unique | Default | Description | Notes |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| `Id` | uuid | No | Yes (PK) | `gen_random_uuid()` | Primary key for the vendor. | Generated by Postgres; never accepted from the client. |
| `Name` | text | No | Yes, (case-insensitive) | — | The vendor's business name. | Unique index on `lower(Name)` `WHERE archivedAt IS NULL`, A duplicate returns `409 Conflict`. Trimmed; cannot be empty. |
| `ContactName` | text | Yes | No | — | A specific person to contact at the vendor. | — |
| `Email` | text | Yes | No | — | General or contact email for the vendor. | Format validated by the API. |
| `Phone` | text | Yes | No | — | Vendor phone number. | Stored as entered. |
| `Website` | text | Yes | No | — | Vendor website. | Must be an absolute URL (`https://…`). |
| `Address` | text | Yes | No | — | Address used when ordering from the vendor. | Multi-line. Copied onto each `PurchaseOrder` when it is created. |
| `AccountNumber` | text | Yes | No | — | Your customer account number with this vendor. | Printed on purchase orders. Not a bank account. Not unique, since different vendors can issue the same number. |
| `Notes` | text | Yes | No | — | Free-form notes about the vendor. | — |
| `CreatedAt` | timestamptz | No | No | `now()` | When the vendor was created. | Database-owned; set once on insert. |
| `UpdatedAt` | timestamptz | No | No | `now()` | When the vendor was last changed. | Database-owned; advanced by a trigger on every update. |
| `ArchivedAt` | timestamptz | Yes | No | — | When the vendor was archived. `NULL` means active. | **Delete rule:** hard delete only when nothing references the vendor (no `PurchaseOrder` rows or inventory). If anything references it cant delete. `PurchaseOrder.VendorId` uses `ON DELETE RESTRICT`, so the database also blocks a hard delete of a referenced vendor. Archiving is blocked while the vendor has open (unreceived or unpaid) purchase orders. Archived vendors are hidden from new work but still shown on old orders; setting `archivedAt` back to `NULL` restores the vendor. |
| `ArchivedBy` | text | Yes | No | — | Who archived the vendor. | The user's JWT `sub`. Set and cleared together with `archivedAt`: `CHECK ((archivedAt IS NULL) = (archivedBy IS NULL))`. |
| `xmin` | xid | No | No | system | Postgres row version. | Built-in system column, not declared in DDL. Changes on every update. Returned as the `ETag` and compared against `If-Match`. In EF Core, map a `uint Version` property to it as the row version. |

- **Id** -- Primary key, generated by Postgres (`gen_random_uuid()`) when the row is inserted.
- **Name** -- The vendor's business name. Required -- a vendor record with no name isn't identifiable.
- **ContactName** -- A specific person to contact at the vendor, if known. Optional since many vendors are just a business name plus general contact info.
- **Email / Phone / Website** -- Contact details, all optional since you may not have all of them for every vendor.
- **Notes** -- Free-form field for anything else worth remembering -- account numbers, special terms, etc.
- **CreatedAt / UpdatedAt / ArchivedAt** -- The standard database-owned timestamp trio used on every table in this schema. `CreatedAt` is set once by a column default when the row is inserted. `UpdatedAt` is set the same way on insert, then advanced by a database trigger on every subsequent update. `ArchivedAt` starts null and is set explicitly by the app when a vendor is deactivated -- soft-deleted rather than actually removed, so old `PurchaseOrder` rows that reference it stay valid.

###  Vendor Rest API's
| Method | Endpoint | Description |
| ----- | ----- | ----- |
| `GET`  | `/vendors`  | List vendors (filterable) |
| `POST`  | `/vendors`  | Create new vendor |
| `GET`  | `/vendors/{vendorId}`  | Get vendor metadata |
| `PATCH`  | `/vendors/{vendorId}`  | Update metadata |
| `DELETE`  | `/vendors/{vendorId}`  | Hard Delete the vendor  |
| `POST`  | `/vendors/{vendorId}/restore`  | Restore archived vendor |
| `POST`  | `/vendors/{vendorId}/archive`  | Archive vendor |
| `PUT`  | `/vendors/{vendorId}/tags/{tagId}`  | Add tag to vendor |
| `DELETE`  | `/vendors/{vendorId}/tags/{tagId}`  | Remove vendor tag |

NOTES:
Archive by default, hard delete only when nothing references it. A vendor created by mistake with no purchase orders can be truly deleted. Anything with history gets archived.
Hide archived vendors from new work, keep them in history.
Check for open business before archiving. Purchase orders not yet received or unpaid bills should block the archive, or at least warn and require them to be closed or cancelled first.

Snapshot vendor details on purchase orders. Store the vendor_id plus a copy of the vendor name, address, and payment terms at the time of the order. A later rename or archive then doesn’t rewrite history

### Vendor API Examples

All requests also send `Authorization: Bearer <token>`, and requests with a body send `Content-Type: application/json`. The examples show only the headers specific to each endpoint. Errors use Problem Details (`Content-Type: application/problem+json`). Any endpoint can return `401` or `403`, so those aren't repeated below.

#### List Vendors
`GET /vendors`

**Query parameters:** (all optional)

| Parameter | Type | Default | Description |
| ----- | ----- | ----- | ----- |
| `q` | string | — | Case-insensitive substring match on name, contact name, email, and tag names. Whitespace is trimmed; blank is treated as absent. Max 100 characters. |
| `tagIds` | comma-separated uuids | — | Only return vendors with these tags. Max 20 IDs. |
| `tagMatch` | `any` or `all` | `any` | Whether a vendor needs any of `tagIds` or all of them. Ignored when `tagIds` is absent. |
| `includeArchived` | bool | `false` | Include archived vendors. |
| `sort` | `name`, `createdAt`, `updatedAt` | `name` | Sort field. Prefix with `-` for descending, e.g. `-createdAt`. Ties are broken by `id`. |
| `cursor` | string | — | Opaque value from a previous response's `nextCursor`. Omit for the first page. Must be sent with the same `q`, `tagIds`, `tagMatch`, `includeArchived` and `sort` as the request that produced it. |
| `limit` | int | `25` | Page size, from 1 to 100. |

**Request:** vendors tagged *Pet Food* or *Medical*


#### Update Vendor
`PATCH /vendors/{vendorId}`

Fields you leave out stay unchanged, and `null` clears a field. `name` can't be cleared. Tags aren't changed here; use the tag endpoints below. `If-Match` is required, and a request without it returns `428 Precondition Required`.

```http
PATCH /vendors/7c2e4b8a-3f1d-4c9e-8b2a-1e6d9f0a0002
If-Match: "8412"
```

#### Delete Vendor
`DELETE /vendors/{vendorId}`

Permanently deletes the vendor. Only allowed when nothing references it

**Request:** *Usopp's Legendary Pet Supply* was added by mistake (Usopp swears it's real) and has no purchase orders.

```http
DELETE /vendors/5d7b1f3a-2e8c-4a9d-b6e1-4f0c2a8d0005
If-Match: "8650"
```

**Response:** `204 No Content`

#### Add Tag to Vendor
`PUT /vendors/{vendorId}/tags/{tagId}`

Adds a vendor tag. Adding a tag the vendor already has does nothing and still returns `204`. No `If-Match` needed, since tag links don't change the vendor's version.

**Request:** Baratie Provisions becomes a preferred vendor.

```http
PUT /vendors/7c2e4b8a-3f1d-4c9e-8b2a-1e6d9f0a0002/tags/9b1e7c3a-5d2f-4e8a-b1c6-0000000000a1
```

**Response:** `204 No Content`


#### Remove Tag from Vendor
`DELETE /vendors/{vendorId}/tags/{tagId}`

Removes a tag from the vendor. Removing a tag the vendor doesn't have does nothing and still returns `204`.

**Request:** Straw Hat Meat Co. left East Blue for the Grand Line.

```http
DELETE /vendors/0b5f9c1e-1997-4a7e-9a10-5d2f8c3e0001/tags/9b1e7c3a-5d2f-4e8a-b1c6-000000000eb1
```

**Response:** `204 No Content`
