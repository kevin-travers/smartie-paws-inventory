### Category

The single group a product belongs to, e.g. Food, Treats, Toys or Grooming Supplies. Each product has at most one category, which decides where it appears on the POS screen and keeps sales-by-category reports adding up to total sales, since every product is counted once. Anything that overlaps -- Dog, Cat, Grain-Free -- is a tag instead. Categories are a flat list with no nesting.

Categories are hard-deleted rather than archived. Deleting one either moves its products to another category or leaves them with no category, which the frontend shows as "Uncategorized."

| Column | Type | Nullable | Unique | Default | Description | Notes |
| ----- | ----- | ----- | ----- | ----- | ----- | ----- |
| `Id` | uuid | No | Yes (PK) | `gen_random_uuid()` | Primary key for the category. | Generated by Postgres; never accepted from the client. |
| `Name` | text | No | Yes (case-insensitive) | — | The category's display name, e.g. "Food". | Unique index on `lower(Name)`. A duplicate returns `409 Conflict`. Trimmed; cannot be empty. |
| `Description` | text | Yes | No | — | What belongs in this category. | — |
| `SortOrder` | int | No | No | `0` | Position of the category's button on the POS screen. | Lowest first; ties broken by name. |
| `CreatedAt` | timestamptz | No | No | `now()` | When the category was created. | Database-owned; set once on insert. |
| `UpdatedAt` | timestamptz | No | No | `now()` | When the category was last changed. | Database-owned; advanced by a trigger on every update. |
| `CreatedBy` | uuid | No | No | — | Who created the category. | Set by the app on insert, from the JWT `sub`. |
| `UpdatedBy` | uuid | No | No | — | Who last changed the category. | Set by the app on every insert and update. |
| `xmin` | xid | No | No | system | Postgres row version. | Built-in system column, not declared in DDL. Returned as the `ETag` and compared against `If-Match`. In EF Core, map a `uint Version` property to it as the row version. |

- **Id** -- Primary key, generated by Postgres (`gen_random_uuid()`) when the row is inserted. The client never sends it.
- **Name** -- The category's display name, shown on the POS button and in reports. Required, and no two categories can share a name, ignoring case.
- **Description** -- Optional note about what belongs in the category, to help staff pick the right one.
- **SortOrder** -- Where the category appears on the POS screen, lowest first. Changed with the reorder endpoint.
- **CreatedAt / UpdatedAt** -- Same database-owned pattern as every other table (see [Vendor](VendorDesign.md)).
- **CreatedBy / UpdatedBy** -- The users who created and last changed the category. Set by the app from the JWT `sub`, since the database doesn't know who's logged in.
- **xmin** -- Postgres's built-in row version. The API returns it as the `ETag`, and updates must send it back in `If-Match`; if the category changed in the meantime, the update is rejected with `412 Precondition Failed`.

**Delete rule:** `Products.CategoryId` uses `ON DELETE SET NULL`, so deleting a category leaves its products uncategorized instead of blocking the delete. Pass `moveTo` to move them to another category first, in the same transaction. The confirmation dialog should say how many products will be affected.

### Category REST APIs
| Method | Endpoint | Description |
| ----- | ----- | ----- |
| `GET`  | `/categories`  | List categories in POS order, each with its product count |
| `POST`  | `/categories`  | Create a category |
| `GET`  | `/categories/{categoryId}`  | Get a category |
| `PATCH`  | `/categories/{categoryId}`  | Update name or description |
| `PUT`  | `/categories/order`  | Reorder categories with `{ "categoryIds": [...] }` |
| `DELETE`  | `/categories/{categoryId}`  | Delete a category; its products become uncategorized, or move to another category with `?moveTo={categoryId}` |
